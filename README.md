# prototype-nov

一款带 Roguelike 元素的 2.5D 回合制小队探索游戏，当前在 `dev/mvp-expedition` 分支开发 MVP。

玩家在迷雾沙盘中寻找补给、结识伙伴、安排角色分头探索，应对敌人与环境，最终完成撤离；没有强制撤离期限。

## 当前方案

- 首版模式：单人生存远征。
- 地图：地块和地图外轮廓均为六边形，中心向外 8 圈、共 217 格，包含平原、森林、山地、遗迹、沙漠、沼泽六类。
- 探索：角色用所在格及一圈六格揭开新区域，全队共享；已探索地块永久点亮、持续可观测，不再离开后暗化，仅未知区域保留迷雾。
- 目标：活着抵达撤离点并确认撤离，没有撤离天数上限。
- 远征队：可以招募多名成员，不再采用五人总上限；角色可以分头行动，总人数是否设软上限待确认。
- 相遇：MVP 每局放入全部六名可招募伙伴，按地形、剧情与生成约束随机安排位置；精灵医者一般在森林相遇，具体场景与偏好表继续细化。
- 出战队伍：只有同一地块的角色能参战，场上同时最多四人；可用同地候补替换，替换占一次正常行动。每名角色本场首次上场支付个人参战行动力，同场再次上场不重复收费。
- 时间：每个角色独立持有每日行动点，上限由该角色的行动力设定决定，不设全队共享额度或统一数值基准，形成战斗力与机动力的取舍。
- 主角：玩家本人也属于角色，与伙伴共用生命、魔力、独立行动力、技能、装备等属性体系及资源规则；参战时同样占用一个出战位置。
- 主角开局可选职业模板，具体职业稍后设计；新伙伴首次加入当天获个人上限 AP，只初始化一次，不凭加入清空伤势。
- 恢复与物资：每天 HP/MP 部分恢复、AP 回个人上限，无每日强制口粮；物资用于恢复和任务。背包不限容量、不计负重，同格免费交接；战斗中仅在自己正常行动时可不限件数用物资，不占正常行动，消耗持有物品。
- 日期与背包：全队共用日期，玩家统一结束一天，提前结束提示剩余 AP；不设每日强制口粮。恢复物资与任务物品由个人携带，只能同格交接。
- 玩法：探索、招募、补给、角色回合制战斗和简单营地；战斗借鉴《崩坏：星穹铁道》的体验方向，支持手动与自动。
- 战斗：连续速度条，普通技能消耗 MP、占正常行动，不统一设置 CD。个人终结技充能只在战斗中由攻击和辅助技能获得，地图采集不充能；可伤害/恢复/辅助，满后间隙插队额外释放、用后清空、战后保留，无弱点条。
- 装备与遭遇：武器、防具、饰品各一槽；敌人强度固定，不按参战人数缩放，入场前提示危险。
- 敌人与伏击：固定驻守，开阔地形部分敌人可见，森林/沼泽可藏伏击；探索点亮不等于敌人透视。伏击 AP 不足也开战、参战费最多扣到 0。具体敌人职责与组合见设计提案。
- 同行与对话：交谈、剧情对话选项、邀请同行和交付任务不耗行动力，无单独收费的招募动作。可直接同行、任务后同行或战后结识，玩家可拒绝。
- 战斗胜败：主角倒下不立即结束战斗；胜利后本战倒下的友方恢复至 1 HP。主角参与的战斗中，场上全倒且没有符合参战条件的健康同地候补时，才判本局失败。
- 重伤与撤离：非主角队伍战败者留在遭遇地点等同地救援，重伤不靠次日自然恢复站起，全队失能无救援则本局失败。到站不自动撤离，可等同伴；玩家主动确认后到站者撤离，异地成员有对应未撤离剧情，不自动判死。
- 核心交互：伙伴与敌人具有属性，技能存在克制，并受地形与天气影响。
- 环境：战斗处理当前格火伤、点燃/灭火等，森林燃料按天消耗、火势日结算沿六邻传播；环境变化保留本局，敌我共用规则。
- 撤离生成：开局给大致方向，进入视野后确定位置；算法必须同时检查与出生点的六边形距离、实际路线成本和可达性，不能生成过近撤离点。
- 表现：探索与战斗均为 2.5D，手绘六边形立体沙盘与固定斜视战斗镜头复用同一套 3D 小人偶及简单骨骼动画；剧情肖像/立绘为日系二次元，统一角色外观。
- 战斗背景：对应实际交战格的平原、森林、山地、遗迹、沙漠或沼泽，并反映燃烧、潮湿、焦土和天气；技能改变环境后，舞台与地图状态一致。
- 剧情：已采用暂名《归灯之野》的世界观与首章《地图上没有的驿站》，以伙伴、地方故事和旧灯路的历史隐情支撑探索及 NPC 对话；名称与细节可继续修订。
- 分支与结局：多条支线、选择分支与多个可探索结局属于核心设计；首章、六人支线和覆盖矩阵已审阅修订，后续按真实状态接入游戏。
- 设计探索：持续梳理冻结、导电、风、地形改造和角色专长等交互；火灾只是环境系统的首个验证案例，不代表全部玩法。
- 重玩：失败后本局重置，新的地图种子改变地图与遭遇。
- 当前技术基线：Godot 4.7.2 标准版、GDScript；`game/` 为 3D 场景/骨骼角色与 2D 界面的 2.5D 工程。

地图大小与基础视野已确定为首版基线；距离门槛、恢复额度、物品效果和角色行动点等数值仍待讨论与验证。无每日强制口粮，没有撤离天数上限。当前工程基线为本地已安装引擎，正式发行平台另行确定。

开发按 [MVP 实现计划](docs/implementation-plan.md) 的 M0～M6 推进，当前成果、真实验证与剩余工作见 [开发进度](docs/development-status.md)。

## 运行开发版

用 Godot 4.7.2 打开 `game/project.godot`，按 F6/F5 对应运行场景/工程；或在仓库根目录执行 `godot_console --path game`。首次用编辑器导入字体资源后运行。

规则检查：`godot_console --headless --path game --script res://tests/test_rules.gd`。`-- --quick` 可用较少种子检查。程序依赖已随工程声明，尚未生成最终试玩包。

## 第一版暂不包含

多人联机、自由结盟、自定义 NPC、堡垒与攻城、复杂经济、完整属性克制网络、运行时 AI 对话和永久数值养成。

## 仓库状态

仓库包含设计文档和开发中的 Godot 工程；当前可运行开发版不等于完整 MVP 或最终交付。

用户已授权开始开发并自行处理剩余待定项；完成整体测试后推送开发分支并提交合并请求，是否合入由用户决定。

服务器上的仓库用于项目开发与 Git 同步，不代表已经部署游戏服务。

## 实施原则

1. 先做可重复验证的规则原型，再补充完整美术与内容。
2. 每阶段交付可检查成果，从探索骨架逐步贯通完整远征，不并行铺开多个模式。
3. Agent 负责实现与辅助测试，玩法判断依赖真实试玩。
4. 随机地图必须可达、有线索、有初期生存机会。
5. 不将密码、访问令牌、私钥、私人路径或运行日志提交到仓库。
