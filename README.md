# prototype-nov

一款带 Roguelike 元素的回合制小队探索游戏，当前处于设计与立项阶段。

玩家在迷雾沙盘中寻找补给、结识伙伴、安排角色分头探索，应对敌人与环境，最终完成撤离；没有强制撤离期限。

## 当前方案

- 首版模式：单人生存远征。
- 地图：地块和地图外轮廓均为六边形，从地图中心向外扩展 8 圈（不含中心格），共 217 格，连续分布平原、森林、山地、遗迹与沙漠。
- 视野：每个角色初始只能看到所在格及相邻一圈六格，边缘自然裁剪；其余区域在迷雾中，随移动探索逐步发现。
- 目标：活着抵达撤离点并确认撤离，没有撤离天数上限。
- 远征队：可以招募多名成员，不再采用五人总上限；角色可以分头行动，总人数是否设软上限待确认。
- 相遇：MVP 每局放入全部六名可招募伙伴，按地形、剧情与生成约束随机安排位置；精灵医者一般在森林相遇，具体场景与偏好表继续细化。
- 出战队伍：只有同一地块的角色能参战，单场最多四人，可以少于四人；异地角色不能远程支援。
- 时间：每个角色独立持有每日行动点，上限由该角色的行动力设定决定，不设全队共享额度或统一数值基准，形成战斗力与机动力的取舍。
- 主角：玩家本人也属于角色，与伙伴共用生命、魔力、独立行动力、技能、装备等属性体系及资源规则；参战时同样占用一个出战位置。
- 玩法：探索、招募、补给、角色回合制战斗和简单营地；战斗借鉴《崩坏：星穹铁道》的体验方向，支持手动与自动。
- 核心交互：伙伴与敌人具有属性，技能存在克制，并受地形与天气影响。
- 环境变化：已确认战斗只推进当前战场环境；建议日结算推进全地图，火势沿六邻格传播。水技能可以灭火、浸湿和阻断传播；变化保留在本局地图中，敌我共用规则。
- 撤离生成：开局给大致方向，进入视野后确定位置；算法必须同时检查与出生点的六边形距离、实际路线成本和可达性，不能生成过近撤离点。
- 美术：手绘桌游风六边形地图，日系二次元角色肖像与剧情立绘，地图和战斗使用同角色的小人偶；以原创生成素材建立统一角色外观，简化动作。
- 剧情：已采用暂名《归灯之野》的世界观与首章《地图上没有的驿站》，以伙伴、地方故事和旧灯路的历史隐情支撑探索及 NPC 对话；名称与细节可继续修订。
- 设计探索：持续梳理冻结、导电、风、地形改造和角色专长等交互；火灾只是环境系统的首个验证案例，不代表全部玩法。
- 重玩：失败后本局重置，新的地图种子改变地图与遭遇。
- 建议技术基线：Godot 4.x 稳定版、带静态类型的 GDScript、2D 表现。

地图大小与基础视野已确定为首版基线，距离门槛、补给和角色行动点数值仍待讨论与验证，不是已经验证的平衡结论。天数没有撤离上限。引擎具体版本及最终发行平台在实现前确认。

## 第一版暂不包含

多人联机、自由结盟、自定义 NPC、堡垒与攻城、复杂经济、完整属性克制网络、运行时 AI 对话和永久数值养成。

## 仓库状态

本次初始化仅提交规划文档，尚未创建 Godot 工程、实现游戏功能或生成可运行版本。

当前用户要求先聊清楚设计，只更新设计文档；不开始工程开发或批量制作资产。

服务器上的仓库用于项目开发与 Git 同步，不代表已经部署游戏服务。

## 实施原则

1. 先做可重复验证的规则原型，再补充完整美术与内容。
2. 每个阶段都能运行一局，不并行铺开多个模式。
3. Agent 负责实现与辅助测试，玩法判断依赖真实试玩。
4. 随机地图必须可达、有线索、有初期生存机会。
5. 不将密码、访问令牌、私钥、私人路径或运行日志提交到仓库。

规划基线日期：2026-11-03。
