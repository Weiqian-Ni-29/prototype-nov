# 项目初期规划

更新日期：2026-11-04。状态：设计与实现计划已整理，尚未开发。本次仅更新文档，不创建工程或制作资产。

开发任务、依赖、交付物与验收统一见 [MVP 实现计划](implementation-plan.md)。本文件保留产品验证目标、当前准备情况与风险；长期模式扩展见 [长远规划](long-term-roadmap.md)。

## 1. 第一阶段要回答的问题

首版要验证的循环是：探索未知区域 → 遇见角色或危机 → 做出有代价的选择 → 改变小队 → 利用新的能力继续远征。

优先验证四个假设：

1. 玩家愿意主动探索，并能根据线索规划路线。
2. 不同伙伴会改变路线、资源管理或战斗选择，而不只是提高伤害。
3. 各角色有限且不同的行动点，让玩家在推进、恢复和交战之间产生可理解的取舍。
4. NPC、技能和环境形成双向交互：属性克制影响战斗，地形与天气改变技能，技能改变地块，地块变化又影响双方。

## 2. 首版定位

单人、2.5D、回合制的小队远征，带随机地图、分支故事和组合构筑。主角从职业模板开局，与每局存在的六名伙伴相遇；可以选择同行、拒绝或帮助后不同行。

地图为半径 8 圈、217 格六边形沙盘，包含平原、森林、山地、遗迹、沙漠、沼泽。角色用所在格及一圈六格揭雾，全队共享探索；已探索地形永久点亮可观察，森林/沼泽等仍可隐藏有迹象的伏击。

每人独立位置、AP 上限和背包，没有统一 6 AP 基准。全队共用日期，HP/MP 每日部分恢复、AP 回各自上限，不强制每日口粮；同地才能交物和救援。战斗同时最多四人，同地候补可换入，按连续速度条行动，支持手动/自动与插队终结技。

探索与战斗复用 3D 小人偶和简单骨骼动画，地图保持手绘桌游风，肖像采用原创二次元风格。战斗固定斜视镜头，舞台反映实际交战格的地貌、天气和燃烧/潮湿/焦土。

目标是找到远处撤离点后由玩家主动确认，没有撤离倒计时或首领钥匙；可以等待同伴，也可以确认后让异地成员进入相应未撤离尾声。剧情采用暂名《归灯之野》首章与六人支线，规则和详细内容以 [MVP 设计](mvp-design.md)、[设计决策](design-decisions.md) 及故事文档为准。

原 20～35 分钟仅为观察局长的起点，具体数值需要试玩，不是平衡结论或工期承诺。

当前没有 Godot 工程和可运行游戏。用户明确启动后，首个任务是 M0 工程与视觉验证，本次更新计划不改变这一状态。

## 4. 实现阶段摘要

| 阶段 | 重点 |
| --- | --- |
| M0 | 工程、导出、角色/规则配置、共用 3D 模型与动画验证 |
| M1 | 217 格地图、个人行动、迷雾、背包、日恢复与主动撤离骨架 |
| M2 | 连续速度条、手动/自动、终结技、候补、参战收费、重伤与救援 |
| M3 | 水火、天气、日结算传播、地貌匹配舞台与三人故事切片 |
| M4 | 每局六名伙伴、完整职业/敌人内容、首章分支与异地尾声 |
| M5 | 2.5D 资产与界面补齐、存档恢复、动画和整体回归 |
| M6 | 安装/运行验证、外部试玩、调整与测试包 |

每个阶段有可运行或可检查的成果，完整远征从 M1 骨架逐步扩充；M0 不要求先做完整一局。三人切片用于验证，不能替代六人完整 MVP。详细任务与验收只维护在 [实现计划](implementation-plan.md)，避免重复版本。

## 5. Agent 实现与验证要求

- 每次任务明确输入、修改范围和可验证成果；实现前读取受影响规则，不自动将候选功能定案。
- 使用原生文本编辑工具修改项目文件，记录工具版本与实际运行方法。
- 规则检查覆盖费用、状态和随机性；实际窗口和导出包检查覆盖画面、输入与完整流程。
- 地图和战斗问题记录种子与操作序列；无窗口测试不替代实际交互检查。
- 引擎 API 与固定版本匹配，不混用 Godot 3/4 的示例。
- 每阶段同步设计变更、检查结果和剩余问题；不向仓库提交凭据、私人路径或内部运行日志。

## 6. 风险与应对

| 风险 | 早期信号 | 应对 |
| --- | --- | --- |
| 探索重复 | 大量移动没有新信息或选择 | 增加线索和有效遭遇，先调整内容密度 |
| 队伍同质 | 同行只增加伤害 | 用职业、技能、机动与支援形成分工 |
| 等待或恢复压过探索 | 原地休整成为唯一合理选择 | 调整恢复、物资获取与目标收益，不加撤离期限 |
| 拆队刷资源 | 编组、切场景或读档刷新预算 | 资源属于角色实例，统一结算和存档 |
| 异地支援失控 | 远处角色提供物品、证物或战斗帮助 | 同地资格校验与可见信息分离 |
| 随机地图无解 | 角色漏放、任务/撤离不可达 | 硬约束、有限回溯/修复、固定种子检查 |
| 3D 制作受阻 | 模型可看但无法绑定或动作变形 | M0 先验证人形与四足制作链，再批量制作 |
| 规则难懂 | 失败原因与界面不一致 | 展示费用、倍率、风险和不可用原因 |
| 故事断裂 | NPC 知道异地信息或材料凭空出现 | 物件、知识、授权与同行状态分别记录 |
| 内容失控 | 切片未通就铺开全部资产与扩展 | 按 M3 切片、M4 内容和 M5 表现门槛推进 |
| 自动开发假成功 | 编译通过但游戏无法操作 | 逐阶段实际运行、存档恢复及导出包验证 |

## 7. 首版暂缓项

多人联机、64×64 地图、自由结盟、攻城、永久角色养成、自定义技能、运行时大模型对话和复杂经济系统。核心循环通过试玩后，再依据 [长远规划](long-term-roadmap.md) 决定扩展。
