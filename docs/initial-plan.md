# 项目初期规划

日期：2026-11-03。状态：设计讨论中，尚未实现。当前只整理设计文档，不创建工程或编写游戏代码。

## 1. 第一阶段要回答的问题

不是先证明可以做出 64×64 地图，而是证明以下循环值得反复游玩：

探索未知区域 → 遇见角色或危机 → 做出有代价的选择 → 改变小队 → 利用新的能力继续远征。

优先验证四个假设：

1. 玩家愿意主动探索，并能根据线索规划路线，而不是随机点格子。
2. 不同伙伴会改变路线、资源管理或战斗选择，而不只是提高伤害。
3. 有限行动点让玩家在推进、恢复和交战之间产生可理解的取舍。
4. NPC、技能和环境形成双向交互：属性克制影响战斗，地形与天气改变技能，技能改变地块，地块变化又影响队伍和敌人。

## 2. 首版定位

单人、2D、回合制的小队生存远征，带随机地图和组合构筑元素。

目标是抵达撤离点并确认撤离，没有撤离天数限制。开局只提供大致方向，地图生成保证撤离点不会离出生点过近且存在合理可达路线。首领是可选挑战，不是胜利必需条件。

已确认：六边形地图；远征队可以有多名成员并分头行动；行动点按角色独立计算，各角色的每日上限分别设定，没有统一数值基准或共享额度。只有同一地块的角色能参战，单场最多四人，支持手动与自动。战斗只推进当前战场环境。

地图已确定为六边形外轮廓，中心向外 8 圈（不含中心格），共 217 个六边形格。每个角色初始视野为所在格及相邻一圈六格，其余区域在迷雾中，需要移动探索。原 20～35 分钟只作局长观察起点，补给、异地成员撤离、战斗资源和角色具体数值还需讨论。

恢复机制已确认：每天生命与魔力恢复一部分，行动点恢复到各角色自己的上限；地块可获取物资，部分物资能用于额外恢复。具体恢复量、道具使用规则、每日口粮与库存制度仍待细化。

美术已选定为手绘桌游地图、原创日系二次元肖像与剧情立绘、地图和战斗中的小人偶。角色已确认具备生命、魔力、行动力、技能和装备栏，详见配套角色与美术文档。

剧情已先采用暂名《归灯之野》的世界观、首章《地图上没有的驿站》与六名伙伴人物方向；细节可继续修订。已确认规则与待定事项集中记录于 [设计决策](design-decisions.md)。

这些参数必须通过试玩调整，不构成完成度或商业成功保证。

## 3. 开始实现前的确认项

| 项目 | 建议默认值 | 确认时机 |
| --- | --- | --- |
| 引擎 | Godot 4.x 稳定版 | 创建工程前固定具体小版本 |
| 脚本 | 带静态类型的 GDScript | 与引擎一起确认 |
| 表现 | 已确认手绘桌游六边形地图、二次元肖像与立绘、小人偶探索及战斗 | 具体构图与比例在设计期确认 |
| 首个测试平台 | 开发设备上的桌面版本 | 第一次运行前 |
| 正式发行平台 | 优先评估 Windows，其他平台分别验证 | 可玩切片完成后 |
| 战斗 | 已确认角色回合制、手动/自动、同地最多四人；行动顺序与魔力机制待细化 | 完成详细设计后再安排原型 |
| 商业形式 | 先验证玩法，再决定买断或其他形式 | 外部试玩后 |

当前文档采用上述建议推进设计，不表示已经完成平台承诺或引擎安装。

以下里程碑仅为后续开发规划，不代表现在开始执行。当前阶段继续澄清补给、角色、战斗与分头行动设计。

## 4. 里程碑与验收

开发按成果推进，不承诺未经验证的固定工期。Agent 自动生成代码的速度不能直接等同于可发行内容的制作速度。

### 交互探索：与工程准备并行

- 维护 MVP 设计第 11.7 节的候选矩阵，覆盖伤害、通行、观察、资源与恢复。
- 确认跨格火灾是必做链条，不将环境系统收缩为单格特效。
- 为导电、冻结通路、风与火烟、土墙和非魔法专长选择少量规则原型，发现可玩组合。
- 按可理解性、决策价值、实现依赖与无解风险挑选首版补充交互，不能仅靠列很多属性名称判断深度。
- 记录每条交互的触发、范围、时序、持续时间、解除方式和敌我后果，再决定制作优先级。

### M0：工程与验证闭环

交付：

- 固定版本的 Godot 工程。
- 能运行的启动界面和占位地图。
- 规则测试入口、日志入口和至少一个桌面导出预设。
- 地图生成、行动结算与战斗规则和界面呈现分离。

验收：

- 从仓库和已声明的工具版本能够启动工程。
- Agent 能运行规则检查并读取报错，而不是只完成文件生成。
- 实际打开游戏确认界面可见、输入可用。
- 导出的程序可以在目标测试设备运行。

### M1：地图与一天的行动

交付：

- 可复现的半径 8 圈、217 格六边形随机地图；如使用更小地图做局部规则验证，应明确标注其用途，不替代 MVP 地图规格。
- 六邻接移动、所在格与相邻一圈六格的视野、迷雾与探索记录。
- 每个角色独立的位置与行动预算、不同角色行动上限、统一日期和待确认的补给日结算。
- 撤离点和成功、失败、重新开始流程。

验收：

- 出生点、初期资源和撤离点连通。
- 撤离点同时满足几何距离与实际路线成本下限；生成失败不悄悄放置近距离撤离点。
- 不能透过已探索但不可见区域追踪移动实体。
- 查看信息免费，执行行动按规则扣费。
- 可以完成至少一局有明确结局的远征。
- 固定种子下结果可复现，不会依赖不可复现的运行顺序。

### M2：招募与战斗可玩切片

交付：

- 三个明显不同的伙伴，建议先做游侠、火术师与水术师，覆盖直接加入和短任务加入。
- 至少两个普通敌人类型，覆盖火、水属性及其环境技能。
- 同地最多四人的角色回合制战斗、手动/自动切换、魔力与技能、基础装备栏及战后结算。
- 角色与技能属性分离、基础水火克制，以及沙漠、晴雨的伤害修正。
- 森林点燃、跨格火势蔓延、水技能扑灭或阻断、烧尽转焦土和持续地图状态。
- 环境交互候选矩阵，区分用户确认必做和需要原型挑选的组合，不只围绕火水伤害加减设计。
- 简单营地与恢复行为。

验收：

- 每个角色持有自己的行动预算，拆分、合并和切换不能刷新点数；参战角色必须同地且最多四人。
- 不同队伍能够产生至少两种合理的探索或战斗策略。
- 一次遭遇只能结算一次奖励。
- 任务目标可达，招募条件、出战资格和选项代价明确，出战满员不阻止继续招募。
- 普通战斗不靠反复点击无意义操作拖延时间。
- 相同水火技能对敌我采用相同规则，伤害预览能解释属性、沙漠与天气的共同影响。
- 能完成一次点燃森林、跨格蔓延、双方承受火场代价、水技能阻断或烧尽转焦土的可玩验证。
- 传播结果不依赖地块遍历顺序，未观察区域不泄露实时状态。
- 地形变化保留在地图上，但不会破坏关键任务和撤离可达性。
- 战斗只推进当前格环境，跨格传播建议在全地图日结算执行；异地角色不因一场战斗被快进。

### M3：完整 MVP

交付：

- 半径 8 圈、217 格六边形地图与无撤离天数限制的完整远征。
- 六名可招募伙伴每局全部放入地图，初遇位置按地形与剧情条件随机安排；四类普通敌人、两类精英和一个可选首领。
- 明确数量和功能的探索事件。
- 晴天、雨天、五种基础地形和可读的属性与环境修正。
- 森林燃烧与焦土影响采集和营地收益，伙伴选择能改变这些结果。
- 局内存档、继续游戏、基础教程与结算界面。

验收：

- 从新游戏到撤离或失败可以完整运行。
- 不出现必需资源只由低概率掉落提供的情况。
- 行动、天气、战斗和补给规则保持一致。
- 游戏重启后能够继续局内进度，但不会复制奖励或错过关键结算。
- 能看懂地图、状态与主要操作；手绘地图、二次元肖像和小人偶保持同角色识别一致。

### M4：外部试玩与发行准备

交付：

- 首轮邀请 5～10 位目标玩家试玩，记录行为和失败原因。
- 修复阻塞、误导界面与明显的单一最优策略。
- 替换不可发行素材，补齐音效、字体和版权说明。
- 面向确定平台的可安装测试包。

验收：

- 至少有试玩玩家主动希望再玩一局，并能解释原因。
- 多种队伍配置有实际可用性，而不是只有一种组合能获胜。
- 玩家可以说明撤离目标、行动预算及主要失败原因。
- 不存在已知的崩溃、卡死、无法结束战斗或无法完成远征问题。
- 完成实际安装与运行测试，而不只确认构建命令成功。

小样本测试用于发现问题，不能用于证明市场规模或销量。

## 5. 初期实现顺序

1. 完成设计确认后再进入实现；先做六边形地图和按角色移动。
2. 迷雾和可见状态。
3. 行动预算、补给和日结算。
4. 撤离与失败。
5. NPC 遭遇、招募与分头行动。
6. 角色生命、魔力、独立行动力、技能与装备栏；同地最多四人的手动/自动战斗、属性克制及局部环境反应。
7. 营地、天气、地形转化后的收益和事件。
8. 存档、教程与结算。
9. 内容补齐、平衡和发行验证。

不先制作大型世界生成器、通用剧情语言、多人后端或自定义角色编辑器。

## 6. Agent 协作要求

- 每次任务有明确输入、允许修改范围和可验证的结果。
- 在原生文件工具中修改项目文本，不用临时脚本覆盖源码或文档。
- 地图和战斗问题记录种子与操作序列，避免仅描述偶发失败。
- 用规则测试检查数值与状态，用实际运行检查交互与画面。
- 无窗口测试不等同于界面验证；缺少试玩或画面验证时明确报告。
- 引擎 API 以固定版本文档为准，不混用 Godot 3 与 Godot 4 的示例。
- 不向公共仓库提交凭据、内部日志或敏感身份信息。

## 7. 风险与应对

| 风险 | 早期信号 | 应对 |
| --- | --- | --- |
| 探索重复 | 大量移动没有新信息或选择 | 增加方向线索和有效遭遇，不先扩大地图 |
| 队伍同质 | 招募只改变总攻击力 | 强化探索能力和角色之间的分工 |
| 原地等待最优 | 营地免费无限产出且没有探索动机 | 讨论补给获取代价、营地收益和探索目标，不用强制撤离期限代替设计 |
| 拆队刷行动点 | 重新编组后预算回满 | 预算属于角色，拆分、合并与切换不重置 |
| 分头行动缺乏代价 | 异地伙伴仍可免费参战或提供加成 | 仅同地可参战，明确技能与资源作用范围 |
| 随机局无解 | 开局缺少补给或关键路线 | 生成时保证可达和初期资源，批量规则检查 |
| 规则过多 | 玩家无法解释失败 | 减少生存数值和叠加修正，展示结果预览 |
| 内容膨胀 | 原型未完成就大量写 NPC 长篇故事 | 先完成三名角色的可玩切片 |
| 自动开发假成功 | 编译通过但按钮不可用 | 每个交付阶段实际运行和交互检查 |

## 8. 首版开发暂缓项

多人联机、64×64 地图、自由结盟、攻城、永久角色养成、自定义技能、运行时大模型对话和复杂经济系统。

只有核心循环通过试玩，才开始增加这些能力。
