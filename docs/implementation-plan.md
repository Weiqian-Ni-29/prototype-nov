# MVP 实现计划

更新日期：2026-11-04。版本：计划 1.2。状态：MVP 0.1.0 已实现并进入试玩交付；阶段成果与实际检查见 [开发进度](development-status.md) 和 [验收记录](acceptance-report.md)。

历史记录：下文的六人、送件与撤离故事属于早期方案，不再作为现行剧情依据。当前《维洛丹》的主线、25 人分支与对话规则分别见 [故事大纲](story-outline.md)、[角色分支](story-branches.md) 和 [对白规范](narrative-dialogue.md)。

本计划将已讨论的玩法、剧情和 2.5D 表现转成有依赖顺序的开发任务。先验证工程与共用 3D 角色，再完成探索、战斗、环境和故事，最后补齐内容、存档与试玩包。每阶段以可检查的成果验收，不承诺未经验证的固定工期。

## 1. 范围与依据

规则以 [设计决策](design-decisions.md) 和 [MVP 设计](mvp-design.md) 为准；角色、相遇、敌人、美术和故事分别沿用对应详细文档。发现冲突先修正规格，再实现，不由代码悄悄决定新规则。

完整 MVP 包含：

- 单人远征，半径 8 圈、217 格的六边形地图，平原、森林、山地、遗迹、沙漠、沼泽六类基础地形。
- 主角可选职业模板，六名伙伴每局各投放一次；可以分头行动，每人独立位置、AP 上限和个人背包。职业的具体数量与内容在 M0 落表。
- 所在格及周边一圈揭雾，全队共享探索，已探索永久点亮、可观察当前地形与状态，但不自动识破隐藏敌人。
- 全队统一日期，每日 HP/MP 部分恢复、AP 回各自上限；无每日强制口粮，无撤离期限。
- 同地同时最多四人出战、候补换人、连续速度条、手动/自动、MP 技能、个人终结技、装备和物资。
- 固定强度的驻守敌人、开阔地可见遭遇、遮挡地伏击及风险迹象；具体敌人名单在制作前选定。
- 当前格战斗环境、晴雨、水火与地形修正、按日消耗燃料和跨六邻格传播的火灾、灭火及焦土。
- 同地救援、非主角队伍战败后留原地、主角战斗全灭与全队失能判定、主动撤离与异地成员尾声。
- 《归灯之野》首章和六人个人支线，包含选项、真实后果、拒绝同行和多结局；局内存档、基础引导与结算。
- 探索与战斗均为 2.5D，手绘立体六边形沙盘、共用 3D 小人偶与简单骨骼动画、二次元肖像；战斗背景对应实际地貌、天气和环境状态。

以下不进入本轮：多人联机、64×64 地图、永久数值养成、攻城与复杂经济、角色编辑器、运行时 AI 对话。候选环境交互和敌人名单不因写入提案就自动全部成为交付承诺。

## 2. 开工前应补齐的规格

以下事项按受影响模块前置处理，不要求所有平衡数值一次定死。用户已授权 agent 自主决断剩余事项，开发完成前不再逐项确认；选择与参数维护于 [实现记录](implementation-notes.md)。

| 规格 | 要完成的内容 | 最晚处理阶段 |
| --- | --- | --- |
| 职业与角色表 | 职业模板、六名伙伴的 HP/MP/AP/速度等属性、攻击、主动技能、被动和终结技；主角遵循同一结构 | M0 定首批，M4 补齐 |
| 移动与恢复表 | 六类地形移动成本、每日恢复比例、恢复物品、采集产出、参战费用、撤离距离及路线成本 | M1 前建立测试配置 |
| 参战与行动条 | 同速顺序、换人进度、全倒补位、候补受伤范围、撤退结果；主动交战和伏击的收费边界 | M2 前确认行为规则 |
| 终结技细则 | 多段攻击如何计充能、终结技自身是否产能、同时申请的队列顺序、隔日能量、自动战斗的使用策略 | M2 前确认行为规则 |
| 重伤与胜败 | 双方同时全倒、主角战斗外归零、救援技能及费用、搬运是否进入 MVP | M2 前确认必要边界 |
| 环境时间 | 火场伤害的战斗触发时点、潮湿期限、每日燃料与天气结算顺序、沼泽实际效果 | M3 前形成时序表 |
| 装备 | 换装时机、费用与装备效果 | M3 前确认 |
| 内容清单 | 首批敌人及完整 MVP 名单、六人地形备选、任务地点与距离、事件数量 | M0 列清单，M4 前冻结首版范围 |
| 视觉规格 | 六边形朝向、镜头角度、头身比、模型尺度、骨架和动作、字体与界面规格 | M0 打样后记录 |

纯数值可先设有版本的测试值并注明来源，随后试玩调整；不能把角色统一成固定 6 AP，也不能借测试配置加入每日口粮、撤离倒计时或共享背包。改变收费方式、胜败条件等行为规则，应先更新设计决策。

## 3. 工程组织与状态边界

以本地已安装的 Godot 4.7.2 标准版和带静态类型的 GDScript 为当前基线。探索/战斗使用 3D 场景，界面与肖像使用 2D；先在开发设备和 Windows x64 导出包上验证，正式发行平台另定。

工程已放在仓库的 `game/` 下，保留现有 `docs/`。下表为原计划职责划分；当前较小规模合并了编排与界面入口，实际目录映射见 [实现记录](implementation-notes.md#实际工程组织)：

| 目录 | 职责 |
| --- | --- |
| `game/data/` | 地形、职业、角色、技能、敌人、装备、物资、故事与测试配置 |
| `game/scripts/domain/` | 地图、角色、背包、遭遇、战斗、环境、任务的状态与结算 |
| `game/scripts/application/` | 行动校验、流程切换、存档和一次性结算事务 |
| `game/scenes/exploration/` | 六边形沙盘、迷雾、选人、移动与地块表现 |
| `game/scenes/battle/` | 行动条、阵容、战斗舞台、动画和技能反馈 |
| `game/scenes/ui/` | 菜单、角色/背包面板、对话、撤离确认和结算 |
| `game/assets/` | 共用模型、材质、骨架、动画、肖像、场景构件、字体与音效 |
| `game/tests/` | 有明确规则断言的自动检查与固定种子场景 |

核心约束：

1. 定义数据与本局状态分离。同一角色只有一个本局实例，切换界面、拆队、进出战斗和重新加入不能复制背包或刷新资源。
2. 所有实际操作先校验位置、资格和资源，再一次性结算。对话、交付、采集、施法和战斗分别遵守自己的费用，不用统一“互动费”覆盖。
3. 同一套规则服务手动与自动；动画播放结果，不负责决定伤害或补发奖励。加速、跳过演出和切换模式不重复结算。
4. 分开处理全局日期、战斗行动时间、界面动画时间。观看动画不推进一天，战斗不更新异地角色或异地火场。
5. 规则随机与视觉随机分离，保存地图种子、规则版本和运行随机状态；固定输入可以复现问题。
6. 地形状态与可见信息分离。共享已探索地形不授予隐藏敌人、异地背包、对白或施法权限。
7. 稳定检查点从 M1 开始接入，各阶段增量保存状态；不等到完整内容做完才补存档。

## 4. 阶段与依赖

主顺序为 M0 → M1 → M2 → M3 → M4 → M5 → M6。美术在 M0 验证制作链后逐步替换占位内容；M3 做通一条故事后，再在 M4 批量接入分支。一个阶段的演示通过不代表完整 MVP 完成。

| 阶段 | 可检查成果 | 完成门槛 |
| --- | --- | --- |
| M0 工程与视觉验证 | 可启动/导出的工程、共用人偶、规格表 | 3D 导入、简单动画、2.5D 镜头与输入实际运行 |
| M1 探索与个人资源 | 可完成探索到主动撤离的骨架 | 217 格、迷雾、个人 AP/背包、日结算与生成约束正确 |
| M2 完整战斗规则 | 可重复验证的手动/自动战斗 | 行动条、终结技、候补、收费、重伤与失败闭环 |
| M3 环境与故事切片 | 探索—战斗—环境—任务—撤离贯通 | 火灾按日传播，当前格战斗环境和真实故事后果连通 |
| M4 完整首章与内容 | 六名伙伴、选定敌人、分支和结局 | 角色投放与任务可达，已定义终点与异地尾声可验证 |
| M5 表现与存档收尾 | 完整 2.5D MVP、稳定继续游戏 | 资产、界面、动画、存档和关键回归检查通过 |
| M6 试玩与测试包 | 可安装试玩包与问题记录 | 在目标设备完成安装、整局游玩与阻塞问题修复 |

### M0 工程与视觉验证

任务：

- 整理第 2 节首批规格，建立带版本的配置与内容清单，明确测试值和待确认行为。
- 建立工程、启动入口、基础日志、规则检查入口与 Windows x64 导出预设，记录启动/导出方式和工具版本。
- 用小型测试场景验证立体六边形选格、斜视镜头、遮挡与 UI；该场景不替代正式 217 格地图。
- 做通一个共用人形模型的材质、骨架、待机/行走/攻击/施法/受击/倒下导入链，在探索与战斗视图复用。先用可替换占位模型验证，不以平面纸偶代替最终 3D 要求。
- 尽早验证四足骨架与动作适配，为砾牙预留独立骨架方案；记录相机下的角色尺度与辨识度。
- 起草存档结构与行动事务编号，检查规则状态不依赖场景节点存活。

验收：从仓库说明启动工程并打开实际窗口，点击与动画可用；导出包能在开发设备启动；同一人偶在两种视图中保持外观一致，动画不会改变规则时间。

### M1 探索与个人资源

任务：

- 实现轴坐标六邻接、边界与距离，生成半径 8 圈、217 格地图，六种地形具有区域连续性和可调移动成本。
- 生成安全起点和远处撤离点，同时检查六边形距离、地形加权路线成本和可达性；预留六名伙伴及关键任务地点的合法候选位置。
- 实现所在格加一圈揭雾、全队共享探索和已探索格当前状态显示，隐藏敌人与未知区域使用独立信息过滤。
- 实现角色独立位置/AP、选人及同行移动的逐人校验、个人背包、同格免费交接、三槽装备的数据和基础面板。多人移动规则在落地前按最终规格处理，不隐含远程跟随。
- 实现采集与恢复物资、统一结束一天、HP/MP 部分恢复和个人 AP 重置；提前结束提示剩余 AP，重伤不自然站起。
- 接入主动撤离确认、等待/取消、重新开始和稳定检查点。骨架结算暂用状态清单，正式故事尾声在 M4 接入。

验收：固定种子可复现；非边缘起始视野为 7 格；拆分、合并、切换和读档不刷新 AP；只有同格可交物或救援。到站不自动结束，超过第 12 天仍可继续并撤离。撤离候选为空时有限次修复/重生成后明确报错，不放宽距离门槛蒙混通过。

### M2 完整战斗规则

任务：

- 以固定测试遭遇验证连续速度条、目标选择、MP 技能、状态效果和手动/自动切换；快角色在相同战斗时间中行动更多次。
- 接入同格选阵、同时最多四人、候补替换占一次正常行动、首次上场收费集合和全倒补位；按确认后的规则处理换人行动条与撤退。
- 实现个人终结技：仅战斗攻击/辅助技能充能，满后在原子行动之间入队释放，清空能量且保留正常行动，战后未用能量保留。地图采集、交谈与进战本身不充能。
- 实现个人持有物资：只在本人正常行动窗口使用，不占正常行动、不限件数；随后仍能攻击或施法。
- 接入普通交战预算检查、伏击风险迹象、首次行动提前及参战费扣至 0 的兜底，敌人不按友方人数缩放。
- 实现胜利后本战倒下友方恢复 1 HP；主角参战时须场上友方全倒且无合格候补继续才判本局失败；非主角败者留原地，接入同地实际救援和全队失能检查。
- 3D 人偶表现攻击、施法、受击与倒下；入场读取实际交战地貌的基础场景，不先接入无关通用背景。

验收：覆盖一人、四人、同地超过四人和异地不可参战；候补本场首次上场仅收费一次。主角倒下仍可获胜，健康但 AP 耗尽不判全队失能。辅助终结技与物资按相同规则生效；动画加速和自动切换不重置行动条、资源或奖励。普通 NPC 交战沿用相同重伤规则，不暗改为非致死切磋。

### M3 环境与故事切片

任务：

- 接入角色/技能属性分离、基础水火克制、沙漠与晴雨修正及来源预览，敌我共用计算规则。
- 当前格战斗处理火伤、点燃、灭火、浸湿；日结算使用快照消耗森林燃料并向六邻格传播，新点燃格不在同次继续连锁。
- 实现潮湿阻断、雨天、燃尽焦土与资源收益变化；关键 NPC、任务与撤离地点保持可达，不后台销毁唯一目标。
- 六类战斗场景叠加实际天气、燃烧、潮湿和焦土；技能即时改变舞台，回地图后保留同一状态，未知邻格的信息不进入背景。
- 建立有限的故事条件/效果执行器，支持免费对话与交付、立即同行、任务后同行、普通交战后救援再邀请，以及帮助但不同行。
- 建议先接通洛恩、弥烬、澄汐的剧情与水火组合，再扩到全员；技术切片可用固定地点，正式每局六人投放在 M4 验收。
- 用实际持有的任务物品贯通一个地方故事和提交结果；到站后等待、取消撤离、最终确认及一名异地成员尾声全部可操作。
- 按候选矩阵分批实现和验证环境交互。

验收：完整走通探索、同行、分头行动、战斗、点火/灭火、跨日传播、交付和撤离。战斗不推进异地火势或提前烧尽森林；调整地块遍历顺序不改变同一日的传播结果。异地证据不能凭共享地图交付，故事不引用尚未当面得知的信息。

### M4 完整首章与内容

任务：

- 六名伙伴每局各出现一次，按地形硬条件、地点标签、任务关联和分布偏好放置；精灵森林偏好必须满足，备选场景先有对应剧情再启用。
- 保证早期安全同行路线和关键任务可达；对难放角色先预留候选、冲突时回溯，有限次修复仍失败则报告种子，不漏放人或随意改地形条件。
- 完成主角职业模板、六人技能/被动/终结技、物资与装备表，体现战斗力、机动与支援差异。
- 按选定名单制作不同职责的敌人与组合，至少验证防护、伏击、环境控制、治疗支援等不同威胁；提案中的八种普通敌人、两类精英、一个可选首领仍以范围确认结果为准。首领始终不锁撤离。
- 接入首章、个人支线、对白选项、回访与环境变体，分别保存“是否同行、个人故事结果、结束时位置/伤势”三条状态。
- 按 [分支矩阵](story-branches.md) 验证当前稿的 7 个主线终点、24 个个人结果、24 个已加入但异地未撤离的基础尾声；未发现/拒绝同行另走相应文本，不混入未撤离名单。
- 证物原件、副本、口述和当事人授权分别处理；证物提交与角色撤离分开，不能因材料到站就让携带者自动到站。

验收：每个已定义终点都有可达的测试前置和正确的结果；至少走通直接同行、任务后同行、战后救援同行、拒绝与暂缓、健康/重伤异地未撤离。选择后果与现场、背包和 NPC 知识一致，不只更换末尾台词，也不承诺穷举所有操作排列。

### M5 表现与存档收尾

任务：

- 完成统一的角色外观设定、二次元肖像/必要表情、共用 3D 人偶、手绘场景构件和技能反馈；人形动作可复用，巨狼使用适配骨架。
- 完成地图和战斗的待机、移动、攻击、施法/终结技、受击、倒下与必要起身过渡，恢复/辅助大招采用符合效果的表现。
- 补齐菜单、职业选择、地图/角色/背包面板、地块行动、对话、战斗、撤离确认和结算；提供不可用原因、目标/费用预览与基础引导。
- 集成字体、音效、音量等基础设置，检查文字可读性、同格多人展示、遮挡与不同窗口尺寸；在目标设备观察帧率和交互响应，确定质量配置。
- 完成一份活动远征存档、版本检查和稳定写入；保存角色/个人背包、地图与探索、环境日编号、故事选择、物件归属、奖励及撤离标记。
- 核对战斗运行态中的行动条、候补、已付费集合和待释放终结技。MVP 按既定稳定检查点继续：未完成战斗恢复同一战前检查点及随机状态，不默认支持战斗中途恢复。
- 明确战前入场事务与参战收费的保存边界，恢复时不重复收费、不重复发奖、不重新抽取同一遭遇的随机状态；读档不重复日恢复或火势传播。

验收：六种地貌、焦土、晴雨和火场/潮湿均有实际画面检查；同角色在地图、战斗与肖像中可识别。退出后继续核对所有关键状态，格式不兼容时提示而不静默覆盖。占位工程或无窗口检查不能替代完整表现验收。

### M6 试玩与测试包

任务：

- 完成下节的规则、随机生成、剧情和存档回归，修复崩溃、卡死、重复奖励、无法救援或结算等阻塞问题。
- 构建 Windows x64 试玩包，在目标设备实际安装/启动、保存/继续、完成成功与失败流程；整理版本、操作说明和已知问题。
- 建议首轮邀请 5～10 位目标玩家，观察目标理解、路线选择、分队风险、环境策略、对话分支和再次游玩的意愿。
- 根据实际失败原因、局长、资源曲线、职业/队伍选择调整配置，不用增加地图面积或强制撤离倒计时代替平衡。
- 整理字体、美术、模型与音效的来源和使用许可；平台、售价和公开发布另行决定。

验收：测试包能独立运行，至少完成一局成功和一局失败；已定义关键分支与边界有检查记录，玩家能理解撤离目标、个人 AP 和主要失败原因。未通过项记录复现种子/步骤及影响，不以构建成功宣称游戏已可发行。

## 5. 美术与动画的制作顺序

| 顺序 | 交付 | 用途 |
| --- | --- | --- |
| 1 | 角色外观表、人形与四足样例、镜头/尺度打样 | 先验证辨识度和骨骼制作链 |
| 2 | 共用模型/材质/骨架与基础动画 | 地图和战斗读取同一资产，避免各做一套 |
| 3 | 六种地貌的地块、道具、战斗场景构件 | 通过组合搭建场景，无需给 217 格各做独立背景 |
| 4 | 燃烧、潮湿、焦土和晴雨效果层 | 从真实状态驱动，不只装饰播放 |
| 5 | 六人及主角职业外观、肖像/表情、敌人差异 | 在已验证的制作流程上扩充完整内容 |
| 6 | 技能音效、界面反馈、细节修整与性能调整 | 服务可读性和手绘桌游整体风格 |

二维角色图不等于可用的绑定模型。每份模型都要经过导入、骨架/权重、动作、材质和目标镜头检查；不能把生成肖像视为 3D 动画制作完成。详细风格见 [美术方向](art-direction.md)。

## 6. 验证与回归计划

测试随模块交付逐步接入，优先覆盖状态、费用、随机性和结局风险；实际窗口与导出包检查覆盖镜头、动画、文字、输入和可操作性。

| 检查组 | 重点 |
| --- | --- |
| 六边形与生成 | 217 个唯一格、六邻接、距离/路径、六人唯一、任务/撤离可达、早期安全同行、生成失败兜底 |
| 多角色与资源 | 不同 AP 上限、拆分/合并/切换不刷新、同格交物、每日一次恢复、重伤不自然复起 |
| 战斗 | 一至四人、候补轮换及收费一次、速度频率、同速、终结技插队、辅助充能、物资时机、自动切换 |
| 胜败与救援 | 主角先倒仍获胜、候补补位、非主角败者留原地、全队重伤、AP 耗尽不失败、双方同时全倒的确认规则 |
| 伏击 | 迹象可察觉、隐藏阵容不泄露、入场 AP 不足仍开战、首次提前后恢复普通行动条 |
| 环境 | 当前格战斗与全图日结算分开、快照传播、雨/湿阻断、燃尽焦土、敌我同规则、不破坏关键目标 |
| 剧情 | 当前稿全部终点、交错顺序、拒绝/回访、普通交战后救援、物件/知识/授权来源与重复交付 |
| 撤离 | 到站不结束、等待/取消、最终名单、异地健康/重伤及个人结果组合、证物已交但角色未到站 |
| 存档 | 同一随机状态、环境日编号、首次收费/奖励只结算一次、失败读档提示、未结战斗恢复同一检查点 |
| 画面与交互 | 2.5D 空间感、共用人偶、简单动作、六类背景/环境同步、迷雾遮挡、UI、独立导出包 |

随机地图先建议使用 200 个固定种子作批量检查，并保留边界与历史失败种子；另以相同种子和操作序列重复运行验证确定性。通过数量和失败原因必须报告，不能用“随机测试过”替代记录，也不能据此宣称所有种子都有数学保证。

每阶段留下运行方式、通过/失败项、复现种子与操作步骤；画面使用实际截图或录屏检查。仅文档检查、代码生成、编译成功或无窗口运行，都不算该阶段玩法验收。

## 7. 完整 MVP 的交付边界

完整 MVP 需要 M0～M5 的约定成果和 M6 的本地测试包验证：可以从职业选择开始，完成一局带探索、同行、战斗、环境和分支后果的远征，退出后能继续，最后由玩家主动撤离或按规则失败。

只完成地图、单场战斗或三人切片时，应标为对应阶段演示；不能省略每局六名伙伴、已定义故事结局、异地成员尾声、2.5D 共用人偶与简单动画后仍称完整 MVP。

MVP 0.1.0 已完成上述功能范围与本机整体检查，Windows x64 以便携包交付。外部玩家体验测试属于后续阶段，未把自动断言数量当作外部玩家验收。代码推送开发分支并提交合并请求，主分支是否合入由用户决定。
