# 单线旅途 · 途中抉择 探索机制设计（PRD）

- 状态：草案（待评审）
- 范围：替换现有六边形世界地图探索，改为「单线前进 + 短剧情 + 赌注可见 / 类型隐藏」的途中抉择循环
- 关联演示：`velodan-encounter-demo.html`（自包含可交互演示）、`velodan-encounter-prd.canvas.tsx`（Canvas 交互稿）
- 基线：`origin/main @ e1318c1`（PR #97 合入后）

## 1. 背景与问题

现有探索基于六边形岛屿地图（`game/scripts/domain/hex_map.gd` 的 `HexMap.generate`）与远征走格（`game/scripts/domain/expedition.gd`）。核心问题：

1. **允许回头路，选择没有机会成本。** `Expedition.move()`（expedition.gd:562）只校验相邻、陆地与步数（`STEPS_PER_DAY=5`），不限制已访问格；玩家可以反复扫图。
2. **探索奖励鼓励全收集。** `visited` 驱动迷雾揭示与探索遗器阈值 `[20, 60, 100]`，最优解退化为「把图扫满」，而非「在岔路中取舍」。
3. **抉择乐趣缺失。** Roguelike 的重量来自「选了一条路就永久失去其他路」；当前自由走格抹平了这种不可逆性。

结论：地图走位本身不是乐趣来源，反而稀释了抉择。本设计**完全舍弃六边形世界地图与自由走格**，把探索重构为一条不可回头的单线旅途。

## 2. 目标与非目标

### 目标
- 每一步都是一次**不可逆**的抉择：未选之路永久关闭。
- 抉择信息**轻量可读**：两三句剧情 + 2–3 个朴素动作选项，玩家几秒内能决策。
- 不确定性**可感知但不可背板**：玩家知道「赌多大」，不知道「具体是什么」，且同一选项不同局结果不同。
- 复用现有战斗 / 商店 / 遗器 / 伙伴系统，不重做底层玩法。

### 非目标
- 不做分层节点地图（常见 roguelike 路线图）——缺乏新意且把抉择提前暴露为图标。
- 不做「路线即_build 契约」式抽象预览——难以在游戏视角直观呈现。
- 不做地形塌陷 / 迷雾收缩等机制——玩家理解成本高。
- 不在本 PRD 内实现游戏侧代码；仅定义机制与文案规范，实施另开任务。
- 不引入稳定的「暗示词 → 节点类型」映射语言（见 §5）。

## 3. 核心循环

单线旅途，固定步数（演示为 7 步：6 段途中 + 1 段终点 Boss）。每一步：

1. **前进一格（不可回头）**：旅途只向前推进，无地图、无走格、无回头。
2. **读两三句剧情**：轻量叙事，交代当下画面与处境（参考杀戮尖塔的轻量事件文本）。
3. **在 2–3 个选项中按赌注抉择**：选项是朴素动作（「循着歌声走进林子」「摸黑蹚过浅滩」），每个选项标注**赌注量级**（低 / 中 / 高），**不标注节点类型**。
4. **揭晓隐藏节点并结算**：选择后按该赌注的节点池加权随机揭晓具体节点（战斗 / 精英 / 宝箱 / 商店 / 休整 / 事件），展示结算摘要（得 / 失）。
5. **进入下一段剧情**：结算后推进到下一步；终点为 Boss 战。

循环要点：**抉择在前、揭晓在后**。玩家决策时只掌握「赌注量级 + 画面氛围」，结果在选后才确定，保证不可逆与不可预览。

## 4. 节点类型与赌注池

### 4.1 节点类型
| 类型 | 说明 | 结算倾向 |
| --- | --- | --- |
| 战斗 battle | 普通卡牌战斗 | 扣生命、给灯铢 |
| 精英战斗 elite | 高压卡牌战斗 | 大额扣生命、大额灯铢 / 遗器 |
| 宝箱 chest | 直接获取资源 | 给灯铢 / 遗器 |
| 商店 shop | 进入现有商店 | 消耗灯铢换卡牌 / 遗器 |
| 休整 rest | 恢复 | 给生命 |
| 事件 event | 轻量随机事件 | 小额得失 |
| Boss | 终点固定战 | 通关判定 |

### 4.2 赌注量级 → 节点池（加权随机）
玩家只见「赌注量级」，类型在池内按权重随机，选后才揭晓。演示权重：

| 赌注 | 标签 | 系数 | 节点池（权重） |
| --- | --- | --- | --- |
| 低 | 可能小得小失 | 0.6 | 休整 35 / 事件 30 / 宝箱 20 / 商店 15 |
| 中 | 有得有失 | 1.0 | 战斗 35 / 宝箱 25 / 商店 20 / 事件 20 |
| 高 | 可能大起大落 | 1.6 | 精英 40 / 战斗 30 / 宝箱 30 |

- **系数**用于缩放结算数值：`结算 = 基础值 × 赌注系数`。低赌注波动小、高赌注波动大，与「敢不敢赌」的直觉一致。
- 同一赌注对应**多种**节点，因此「选高赌注」不等于「必打精英」，只是进入高波动池。
- 权重与池构成可配置（按章节 / 难度调参），但**对玩家隐藏**。

### 4.3 终点
最后一步固定为 Boss，单一高赌注选项，进入现有 Boss 战流程；通关后结算整程。

## 5. 不确定性设计原则（不可背板）

1. **氛围而非密码**：剧情与选项只给画面与处境，**不编码节点类型**；不存在「提到 X 就是战斗」这类可背诵的暗示词。
2. **赌注可见**：每个选项标低 / 中 / 高，玩家知道可能得失的**量级**，据此决定敢不敢赌——这是唯一稳定、可读的决策信息。
3. **类型隐藏**：具体是战斗 / 商店 / 宝箱，选后才揭晓；决策阶段不预览结果。
4. **无法背板**：结果按权重随机，同一选项不同局会落到不同节点；玩久了也猜不死，避免退化为记忆表。

> 设计取舍：曾考虑「稳定的感官暗示语言」（如固定词缀对应固定节点），被否决——玩家会迅速解码并背板，抉择重新变成查表。故彻底移除暗示词，仅保留「赌注量级」这一稳定信号 + 随机池。

## 6. 数值与结算

- 资源：灯铢（货币）、生命（演示上限 30）。
- 结算按节点类型给基础得失，再乘赌注系数（0.6 / 1.0 / 1.6）。
- 战斗 / 精英以**结算摘要**呈现于抉择循环演示中；正式实现接入现有卡牌战斗（含 PR #95/#96 的收藏 / 卡组 / 费用体系与 PR #97 移除元素 / 天气后的规则）。
- 生命归零判定失败；灯铢下限 0。
- 探索遗器阈值（旧 `[20,60,100]` 按 visited 格数）随地图一并废弃，改为按「旅途步数 / 抉择结果」重新设计（另开任务，不在本 PRD 定死）。

## 7. 与现有系统的衔接

- **卡牌战斗**：战斗 / 精英 / Boss 节点直接调用现有战斗入口，沿用卡组与费用规则。
- **商店**：shop 节点进入现有商店界面。
- **遗器 / 伙伴**：宝箱 / 精英 / 事件可产出遗器或伙伴相关奖励，沿用现有获取逻辑。
- **地图 / 远征**：`hex_map.gd`、`expedition.gd` 的走格与迷雾揭示在本机制下不再使用；保留代码但由新旅途流程取代入口（实施期决定删除或归档）。
- **存档**：旅途进度（当前步、已揭晓历史、资源）需可序列化；旧地图存档的迁移策略在实施期定义。

## 8. 剧情与选项库规范

- **轻量**：每段剧情 2–3 句，单屏可读（遵循故事分页约束：每页 3–5 行、约 ≤90 字/屏）。
- **语气**：说书人神话腔，不写圣徒腔、不写歧义压缩句、不用方言词、不做叙述者眨眼式结尾。
- **选项**：朴素动作描述，2–3 个；每个选项绑定一个赌注量级，**不绑定固定节点类型**。
- **无暗示词**：文案不得建立稳定的「词 → 类型」映射；画面氛围可多样，但不可被解码为确定结果。
- **库结构**：`encounter = { place, title, text, choices: [{ label, stakes }] }`；节点池与权重独立配置，便于调参而不改文案。
- 演示提供 7 段示例（谷口 / 废窑 / 渡口 / 林间 / 山道 / 荒营 / 终点），正式库需单独编写并扩充。

## 9. 交互演示说明

- `velodan-encounter-demo.html`：自包含 vanilla-JS 演示，本地静态服务即可运行；完整可点选「抉择 → 揭晓 → 结算 → 下一步」循环。
- 设计者视角开关：开启后显示各赌注的节点池权重条与说明，便于评审调参；玩家视角默认隐藏。
- 页面文案已统一为「单线旅途 / 途中」。
- Canvas 稿 `velodan-encounter-prd.canvas.tsx` 与 HTML 演示同构，用于 IDE 内预览与持久状态。

## 10. 验收标准

1. 旅途单线向前，任意一步不可回头；未选选项不可再选。
2. 每步展示 2–3 句剧情 + 2–3 个选项，选项仅标赌注量级，不显示节点类型。
3. 选择后按对应赌注池加权随机揭晓节点并结算；同一选项多次运行可落到不同节点。
4. 文案不存在可背诵的「暗示词 → 类型」稳定映射。
5. 战斗 / 商店 / 遗器 / 伙伴节点正确接入现有系统。
6. 终点为 Boss，通关 / 失败判定正确。
7. 旧六边形地图与自由走格不再作为探索入口。

## 11. 风险与开放问题

- **随机挫败感**：高赌注连续落精英可能劝退；需保底 /  pity 或池动态调节（开放）。
- **剧情量**：轻量文案仍需足够库容量避免重复；需评估章节文案规模。
- **旧存档迁移**：地图存档如何过渡到旅途进度（开放，实施期定）。
- **探索遗器重设计**：旧阈值废弃后的替代获取曲线（开放）。
- **赌注可读性**：低 / 中 / 高是否足够直观，是否需补充「可能得失范围」提示（开放，注意不要泄露类型）。

## 12. 实施拆分（建议，另开任务）

1. 旅途状态机与序列化（步数 / 历史 / 资源）。
2. 节点池配置 + 加权随机揭晓 + 结算缩放。
3. 抉择 / 揭晓 UI（复用演示交互）。
4. 接入战斗 / 商店 / 遗器 / 伙伴入口。
5. 剧情与选项库编写（遵循 §8）。
6. 旧地图入口替换 / 归档与存档迁移。
7. 探索遗器曲线重设计。
## 13. 游戏内实现

- 每趟选用六段途中故事，分三程各取两段，随后到战鼓台。途中素材库有 12 段，每段三个动作。旅途种子固定故事顺序和各选项的随机结果。
- 选择、遭遇结算和继续前进都写入存档。读档可回到已揭晓的节点，战斗从开战前恢复。玩家可以在「旅途记录」回看选择和实际得失。
- 采用第 4 节的赌注池和系数。保留现有生命上限，休整和途中伤害按生命上限计算。完成第三段时，尚未取得「生命之种」的队伍会获得它。宝箱和胜利仍有各自的遗器奖励。
- 商店通过途中抉择进入。战斗结束先展示战利品，确认后回到旅途。普通和精英战可负伤撤退，决战必须分出胜负。
- 继续旧版远征时，未完成的跑图进度从第一段旅途重新开始。已取得的伙伴、卡组、装备、遗器、灯铢和已作出的角色决定会保留。已结束的远征可查看原有结局。原始地图存档另存为 `expedition.json.legacy-map.bak`。
