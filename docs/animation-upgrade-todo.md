## 3. 分阶段执行与完成条件

执行依赖：A 授权准入 → B 实机样板 → C 资产与动画接入 → D 战斗事件与特效 → E 专属终结技 → F 全量验收。全部任务由实现 Agent 执行，素材准入必须先于任何资产接入；骨架与特效可在样板通过后并行，不能在接口未稳定时各自改同一文件。

### B：在实际游戏镜头中选出最优组合

- [ ] B01：完成主库与对比库免费层的资产清单，记录实际格式、骨架、动作名称、帧率、贴图、文件体积和许可证；筛掉无免费可用文件的候选。
- [ ] B02：用同一地图、战场、灯光和屏幕尺寸制作四个样板：一名近战人形、一名弓手、一名法师和砾牙；每个样板播放待机、移动、攻击/施法、受击、倒下及恢复状态。
- [ ] B03：对通过授权的组合做实际帧对比评分：镜头下可读性与视觉完成度 30、动作质量与覆盖 25、骨架/格式适配 20、角色身份与美术一致性 15、渲染性能 10，总分 100；授权不合格直接淘汰，不参与评分。
- [ ] B04：修正脚滑、肘膝扭曲、武器穿身、朝向和比例后再评分；不能因为下载现成库就视为适配完成。确定一套人形主骨架和动作主库，其他库只补缺，不为每个人随意挑不同画风。
- [ ] B05：保存同场景升级前后截图和短动作录屏，记录最终选择、被淘汰候选和未解决缺项；样板未通过不扩展全队，也不降低目标回到原来的摆肢动作。

样板完成条件：四种角色在探索和战斗中均清晰、稳定且可操作，动作和实际身份一致；免费素材许可与可复现导入路径已确认。

### C：资产整理与骨架动画接入

- [ ] C01：在现有 `game/assets/` 内按模型、动画、特效和许可整理本次确需使用的资源；只提交合法且必要的源/运行资源，不提交整个下载库、Godot 缓存、访问凭据、个人路径或无关工具。
- [ ] C02：优先 glTF/GLB；FBX 可用时验证导入，必要时由 Agent 使用 Blender 转换。锁定比例、前向轴、静止姿态、根节点和骨骼映射，并记录可复现步骤，不依赖付费导出器或付费源文件。
- [ ] C03：按 [Godot 骨架重定向](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html) 设置人形 BoneMap/SkeletonProfileHumanoid，修正静止姿态和比例；动物单独处理，不强套人形 Profile。
- [ ] C04：修改 `game/scripts/presentation/doll.gd`，接入完整骨架模型与 AnimationPlayer/AnimationTree；保持同一角色资产在地图和战斗复用，不保留会同时驱动同一骨骼的旧 `_process()` 程序化姿态写入。
- [ ] C05：建立本次实际需要的动作映射：idle、walk/run、近战攻击、弓攻击、施法、辅助施法、防守、hit、down、recover；身体类别共享动作，角色配置决定模型、武器和特效。动作缺项要显式补齐，不静默把所有动作映射成 cast。
- [ ] C06：地图使用原地行走/跑步动画，由现有移动逻辑决定位移；根运动禁用或正确消除，不能动画和平移各移动一次。按实际速度调整播放速率，处理连续点格与同格队员偏移，不脚滑、跳回原点或重叠补间。
- [ ] C07：战斗角色保持实际阵位；近战踏步、扑咬和后退只作用于呈现偏移，不能修改六边形位置或额外触发移动/参战成本。攻击后返回原位，远程角色不一律冲向目标。
- [ ] C08：为三种主角职业和六名伙伴配置身份特征：岑枝弓与林地配色、洛恩轻装信使、伊芙精灵耳与医者装束、砾牙狼形与扣环、弥烬火术配色、澄汐水术配色；不得覆盖既有肖像、姓名和剧情身份。
- [ ] C09：覆盖棘背兽、荒路弩手、苔伏蛛、淤泥潜伏者、炉心守卒、渠台守卫、巢鸣蜂群、拾荒药师、两种精英和旧驿灯卫；四足、蜘蛛、蜂群、构装、人形的轮廓和动作区分明确。
- [ ] C10：稀缺动物/怪物动作先继续筛选合规免费来源；仍缺的动作由 Agent 在已许可骨架上修复或补做最小完整片段，记录缺项与修复，不改用别人的非商用素材，也不把怪物全部换成人形。
- [ ] C11：HP0 播放倒下并保持不能行动的状态，不自动起身或预言死亡；只有正式救援/胜后恢复使状态改变时才起身。存档加载直接恢复真实伤势，不重播造成重复逻辑效果的动画。

完成条件：所有当前角色和敌人均有适配后的完整基础动作，探索/战斗不闪现、不扭骨、不丢模型；资源与玩法规则保持不变。

### D：事件分发、技能特效与反馈

当前入口：`game/scripts/domain/battle.gd` 产生 `attack/cast/ultimate/heal` 事件；`game/scripts/main.gd` 的 `_after_combat_step()` 调用 `world_view.gd` 的 `animate_events()`。现有事件把不同技能简化成动作种类，目标通常播放 hit，终结技只放大光点。升级不能仅更换模型而保留这些演出缺陷。

- [ ] D01：为呈现事件补充稳定的技能标识与必要只读结果，区分伤害、治疗、护盾、物品、防守和环境变化；以本次实际结算的目标/结果播放，不从展示名称猜效果，不为了动画改技能规则。
- [ ] D02：修正治疗和护盾目标反馈，普通治疗与辅助终结技不能一律播放受击。HP0、护盾吸收和无伤害辅助动作各有正确表现；施法者也是目标时不被自身目标动画覆盖。
- [ ] D03：加入轻量演出队列或等价的明确时序，保证自动战斗、多人群体目标和终结技插队时动作/特效不丢、不互相覆盖；正常行动和能量结算仍由领域层决定，不能按动画帧重复扣资源或加充能。
- [ ] D04：将施法起手、发射、命中和目标反馈对齐；群体技能覆盖真实目标，不重复做单体伤害。事件已结算后，角色倒下也不能让该动作的攻击演出无故消失。
- [ ] D05：改造 `world_view.gd` 的 `_projectile()`：弓攻击使用箭矢/轨迹，近战使用武器划痕与命中，火术使用火团/火环，水术使用水弧/水滴，治疗使用上升光点，护盾使用包覆轮廓；普通攻击依旧是普通属性，不因人物配色变成元素攻击。
- [ ] D06：用 Kenney 的已许可纹理和 Godot 自带粒子/网格组成特效，优先现有 Compatibility 可运行的实现；不引入只支持 Forward+ 的特效依赖，不为表现新增冰、雷、风或地形改造玩法。
- [ ] D07：显示清楚的命中、治疗与护盾反馈，并与真实结果一致；保留现有中文 UI、阵容和血条可读性，不能只靠颜色分辨目标。
- [ ] D08：环境变化更新现有战场，不因森林点燃/浸湿而重建并打断所有角色动作；地图火焰、湿润、焦土和雨与实际状态一致，不让特效推进异地火势、消耗长期燃料或揭露未知格/隐藏敌人。
- [ ] D09：特效正常结束、战斗结束、撤退和重新开局时回收；镜头短震动/推近后回到原构图，不能永久漂移。根据实际性能决定是否复用对象，不预先堆复杂特效框架。

完成条件：看画面能判断谁行动、打/治/保护了谁、发生了什么环境变化；所有反馈都与实际结算一致。
